# 第一版性能基线

最近复测：2026-07-29

## 测量方法

运行 `pnpm benchmark`。基准场景包含：

- 200 个持续运动的动态小球；
- 500 个双面静态直线碰撞段；
- 10 个矩形重力场；
- 20 个弹簧连接器；
- 固定物理步长 `1/120 s`，关闭物体间静电作用。

测试在 Windows、Node.js `v24.18.0` 下运行。受当前执行环境权限限制，未读取 CPU 型号，因此结果只作为本机基线，不当作所有电脑的性能承诺。

## 2026-07-21 结果

| 指标 | 结果 |
| --- | ---: |
| 平均单步耗时 | `2.1732 ms` |
| 第 99 百分位单步耗时 | `4.2294 ms` |
| 平均吞吐 | `460.16 steps/s` |
| 样本数 | `553` |
| 相对误差 | `±2.61%` |

在固定 `1/120 s` 下，1× 实时模拟平均每个 60 FPS 渲染间隔需要完成两个物理步。平均值和第 99 百分位均小于每步 `8.33 ms` 的预算，因此该物理负载达到实时目标并保留渲染余量。

此次优化把单面碰撞的候选检查从“每个地面都反复跨越 WASM 读取所有刚体状态”，改为“每步只读取一次刚体状态，再用保守包围盒筛选”。优化前同场景平均单步约 `44.55 ms`，优化后约 `2.17 ms`；物理规律测试和浏览器回归均重新通过。

## 2026-08-01 完全弹性曲面碰撞修复复测

完全弹性修正只在场景同时存在“开启碰撞的小球”和“组合摩擦为 `0`、组合弹性为 `1` 的地面”时启用；建场时预先计算资格，普通材质场景整段快速退出。发生短暂碰撞且步末已分离时才扫掠解析地面片，持续路径和普通 Rapier 接触不增加全局曲面扫描。

本轮 `pnpm benchmark` 执行期间，Windows 总 CPU 连续约为 `81%～90%`，`WorkloadsSessionHost` 与系统服务持续占用处理器。完整串行基准中的未改动图表重算 P99 同时升到 `151.07 ms`，五个物理场景分别出现 `3.8860～68.2925 ms` 的 P99，因此这组结果记录为系统抢占异常，不替换既有稳定基线，也不放宽 `<8.33 ms` 目标。

提高测试进程优先级后的隔离复测中，圆轨道、物块连接、弹簧和杆场景 P99 分别为 `5.8314 ms`、`2.4628 ms`、`4.9083 ms` 和 `4.5584 ms`；最大场景平均耗时为 `4.7526 ms`，但仍受 `27.7233 ms` 调度峰值影响，P99 为 `19.4655 ms`。因此本轮确认了普通材质快速退出和四个隔离场景预算，最大场景的安静环境 P99 仍应在系统负载恢复后按相同命令复测，不能把当前离群写成达标结果。

## 边界

- 这是物理核心基准，不等同于不同显卡和屏幕分辨率下的完整 UI 帧率；
- 多坐标系基准测量公式求值和共享缓冲区，不包含不同显卡上的 ECharts 绘制时间；真实浏览器交互由 Playwright 用例和视觉回归另行覆盖；
- 物体间静电作用仍为 `O(n²)`，大量带电物体需要单独测量；
- 极端高速、密集碰撞、高刚度弹簧或复杂杆闭环会增加求解成本；弹簧内部子步上限为 32，超过实时稳定范围时会限制运行时有效刚度并警告；
- 架构调整前应保留本文件并重新运行同一基准，避免用主观流畅度代替测量。
