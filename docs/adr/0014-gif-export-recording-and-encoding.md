# ADR 0014：运动 GIF 的历史记录、渲染与编码

## 状态

已接受。初始实现随应用版本 `1.3.0` 发布；导出交互与成片倍速在 `1.3.1` 完善。场景格式继续使用 `schemaVersion: 7`。

## 背景

图表历史只记录被图表引用的物体，采样集合和频率会随图表配置变化，不能稳定支撑“随时导出刚才的运动”。重新模拟又可能因用户操作、随机扰动或未来求解器变化而与屏幕上已经发生的过程不一致。GIF 编码还会长时间占用 CPU 和较大内存，不能阻塞物理 Worker 或界面线程。

## 决策

1. 物理 Worker 使用独立 `GifTelemetryBuffer`，按模拟时间固定 `30 Hz` 环形记录最近 `300 s`。每个参与模拟的动态物体只保存位置、角度、线速度和合外力七个 `Float32`。
2. 记录上限为 `200` 个动态物体。超过上限时整段 GIF 历史进入阻塞状态并警告，不静默选择部分物体；减少物体并重置后恢复。
3. 打开导出窗口时立即暂停，从 Worker 一次性取得只读 TypedArray 快照，并冻结场景。导出不重新运行物理，也不把历史或设置写入场景。
4. 输出帧在相邻样本间插值，角度沿最短方向；缺失区间保持断开。轨迹从导出区间起点累计，并按输出像素精度简化。
5. 导出复用 Pixi 场景渲染规则，但独立传入轨迹、速度和合力对象集合；隐藏选择框、控制点、工具草稿等编辑覆盖层。
6. 专用编码 Worker 使用 `gifenc`。先从代表帧建立全局调色板，再按顺序接收、编码和释放 RGBA 帧；透明模式预留一个二值透明索引，帧延迟按百分之一秒交替分配以保持平均播放速度。
7. 导出负载上限为 `500,000,000` 像素帧，编码结果上限为 `512 MiB`。超限或取消时终止 Worker 并释放渲染资源，不生成不完整文件。
8. 文件保存优先使用 `showSaveFilePicker`；不可用时回退到浏览器下载。保存位置只能由按钮点击直接请求，完整编码成功后才写入。
9. `1.3.1` 将裁剪轨道和预览进度合并为统一时间轴：灰色表示完整历史、蓝色只表示出入点区间，可拖动倒三角表示当前预览时间。实际导出矩形按输出宽高比居中显示，四边保留棋盘格非导出区域。
10. Pixi 预览渲染器在导出窗口生命周期内只初始化一次；改变分辨率只安全调整其像素尺寸。渲染、调整尺寸和像素读取都必须等待初始化完成。
11. 成片倍速限定为 `0.25× / 0.5× / 1× / 2× / 4×`。输出时长等于模拟区间时长除以倍速，第 `N` 帧读取 `入点 + N × 倍速 ÷ FPS` 的历史状态；倍速不重新计算物理。

## 结果

- GIF 与用户实际看到的本次模拟历史一致，不受图表选择影响。
- 满载历史约占 `50～55 MiB`，但只位于物理 Worker，打开导出时才复制一次快照。
- 编码不会阻塞物理线程，主线程只负责逐帧渲染与进度交互。
- GIF89a 的索引色和二值透明限制会牺牲部分渐变与透明边缘质量；界面明确提示这一格式边界。
- 本决策不引入 MP4/WebM、历史持久化或离线重新模拟。
