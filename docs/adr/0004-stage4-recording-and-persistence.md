# ADR 0004：阶段 4 运行记录与浏览器存档

- 状态：部分被 ADR 0011 取代
- 日期：2026-07-21

图表配置、共享采样缓冲区和导出格式已由 [ADR 0011](./0011-multi-coordinate-charts-and-expressions.md) 取代；本 ADR 中关于文件写入、摘要校验、IndexedDB 草稿和正式存档边界的决策继续有效。

## 决策

物理量记录由物理 Worker 按模拟时间采样，默认 `60 Hz`。Worker 只采集当前曲线涉及的物体，并随渲染帧批量发送样本；主线程按曲线配置提取指标。每条曲线使用有上限的先进先出缓冲区，默认保留 300 秒，最多同时配置 10 条。

曲线配置包含实体 ID、指标 ID、显示名、实体颜色和单位。加速度、合力与动能由物理步状态直接给出，禁止由相邻屏幕帧估算。CSV 使用所有曲线采样时刻的并集，表头包含显示名和单位。

场景格式升级为 `schemaVersion: 2`，增加记录频率和时长设置。迁移按独立纯函数执行 `1 -> 2`，并保留未知字段。

文件保存优先使用浏览器 File System Access API：先在内存中完成序列化和校验，写入关闭后重新读取并比较 SHA-256 摘要。不支持该 API 时明确退化为下载。自动恢复草稿只写入 IndexedDB，不冒充正式保存；应用重新打开时由用户决定恢复或丢弃。

## 原因

- 按模拟时间采样可让 0.25× 到 4× 倍速得到一致的数据密度；
- 批量消息避免每个 `1/120 s` 物理步触发 React 更新；
- 有界记录能预测内存使用，达到上限时的行为清晰；
- 直接文件 API 能实现真正的“保存”，下载回退仍兼容其他浏览器；
- 摘要复核能发现写入后内容不一致，草稿与正式文件分离能避免静默覆盖。

## 未采用方案

- 不记录所有物体的全部指标：大场景会产生大量无用数据；
- 不从渲染位置差分加速度：帧率和倍速会污染结果；
- 不把草稿放入 `localStorage`：容量有限且同步写入会阻塞主线程；
- 不在旧浏览器中声称覆盖原文件：下载行为与直接保存语义不同。

## 边界

第一版不实现任意时间回溯或倒放。曲线缓存丢弃最旧数据前会提示；需要长时间完整实验时，应在到达上限前分段导出 CSV。
