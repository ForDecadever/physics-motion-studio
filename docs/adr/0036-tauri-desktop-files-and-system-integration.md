# ADR 0036：Tauri 桌面文件与系统集成

- 状态：已接受
- 日期：2026-07-30
- 应用版本：1.6.2
- 场景格式：`schemaVersion: 22`（随 Web 版同步演进，桌面集成不引入额外迁移）

## 背景

Web 版已经具备场景校验、迁移、草稿恢复、直接保存和下载回退。桌面版需要原生文件对话框、`.motionstudio` 文件关联、单实例、最近文件、系统菜单和统一的未保存确认，同时不能让前端获得任意本地路径读写能力。

## 决策

1. 使用 Tauri v2 封装 Windows x64 桌面版，生成未签名、每用户安装的 NSIS 包。
2. React 业务层只依赖 `SceneFileService`。Web 实现保留 File System Access API 与下载回退；桌面实现通过受限 Tauri 命令调用 Rust。
3. 桌面前端只保存 Rust 生成的不透明文档令牌。路径映射仅存在 Rust 进程状态中；读取仅来自系统打开对话框、最近文件记录或受支持的启动参数。
4. 桌面读取继续限制为 10 MB，并复用 JSON 解析、逐版本迁移与 Zod 校验。写入完成后回读并校验 SHA-256，失败时不把文档标记为已保存。
5. 新文件默认扩展名为 `.motionstudio`；`.motion.json` 与 `.json` 保持兼容。场景结构随 Web 版演进，不因此增加额外 schema 迁移。
6. 单实例插件最先注册。首实例与后续实例的受支持文件参数进入同一个待打开队列；当前有未保存修改或 GIF 模态时，由前端统一确认后再替换文档。
7. 最近文件保存在 Tauri 应用数据目录，最多 10 条，Windows 路径不区分大小写去重；失效记录在打开失败时删除。
8. 桌面版使用原生窗口菜单，Web 版保留 HTML 菜单。两者通过 `AppCommand` 调用同一处理函数；桌面快捷键交给原生菜单，避免前端重复执行。
9. 能力配置只开放事件、菜单和当前窗口生命周期所需权限。文件对话框与文件读写均由显式 Rust 命令完成；不启用 Shell、HTTP、遥测或宽泛文件系统插件权限。
10. 窗口标题显示场景名与未保存标记，所有退出入口共用未保存确认。

## 结果

- Web 与桌面复用同一场景业务流程，运行平台差异被限制在服务边界。
- 文件关联和最近文件不会绕过扩展名、大小、解析与校验规则。
- 不透明令牌减少了前端脚本误用任意本地路径的能力。
- Windows 安装包在未配置代码签名时会显示信誉提示；发布说明必须明确告知用户。

## 未采用方案

- 直接在前端启用宽泛文件系统插件权限：路径范围过大，难以证明场景来源经过授权。
- 把本地绝对路径写入场景文件：会泄露设备信息并破坏跨设备可移植性。
- 让原生菜单和 React 同时监听同一快捷键：会造成保存、撤销或单步执行两次。
- 首版增加自动更新、托盘、多窗口或网络服务：超出本阶段安全边界。
