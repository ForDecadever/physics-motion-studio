# ADR 0001：固定步长的 Worker 物理内核

状态：已采用<br>
日期：2026-07-21

## 决策

使用 Rapier 2D compatibility build 作为二维刚体求解器，并让物理世界在 Web Worker 中以固定 `1/120 s` 步长运行。React 和 PixiJS 只接收运行时姿态，不直接修改求解器状态。

## 原因

- 固定步长让结果可复现，也便于与解析公式对照；
- Worker 可避免复杂场景阻塞菜单、画布和属性面板；
- compatibility build 将 WASM 内联，能够稳定支持接触过滤钩子，并可在 Vitest 与浏览器 Worker 中使用同一套核心代码；
- 播放倍速通过增加或减少固定步数实现，不会因放大时间步造成额外不稳定。

## 代价

- Worker 构建产物比外置 WASM 方案更大；
- 文档编辑状态与运行时状态必须分开管理；
- 后台落后过多时必须限制追赶步数，并明确丢弃过期时间。
